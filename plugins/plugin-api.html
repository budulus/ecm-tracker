Plugin SDK reference

Extend the Tracker.

ECM Tracker is extensible through small Python plugins for post-processing, export, and visualization. Read the tracked points, draw on the canvas, capture the mouse — without ever touching the core tracking code.

Read & analyze

Tracked coordinates, per-point quality metrics, frames, the ROI and the active mask — all read-only.

Draw overlays

Register a painter that runs every repaint, in screen space, on top of the live frame.

Capture the mouse

Take over canvas clicks to draw zones, pick points, or build interactive tools.

The whole API is one object. Your plugin is handed a PluginContext as self.ctx; it wraps the main window and hides the tricky internals. Learn ctx and you know the SDK.

Overview

What a plugin is, where it lives, and the rules of the road.

A plugin is a self-contained folder under plugins/ that adds a launchable window to the app. ECM Tracker scans plugins/*/ on startup, imports each as a Python package, and lists the ones that expose a plugin.

  • Scope. Plugins are for analysis, export and overlays. They get rich read access to the tracking session, can navigate and re-scope the frame range, and have one undoable point filter — but never touch the tracking algorithm or rewrite a result.
  • One import. Everything you need comes from the app.plugins package: TrackerPlugin, PluginContext, CanvasInteraction, PluginSignals.
  • Shared environment. Plugins run in the app's own Python. You may use the standard library and anything already bundled (NumPy, SciPy, matplotlib). Import heavy/optional deps lazily, at point of use.
  • Crash-isolated. A broken plugin can't take the app down — a failed import shows up as a disabled ⚠ button, a failed overlay quietly removes itself, and a failed launch pops a dialog.

The canonical reference is the source. Every method on ctx is fully docstring'd in app/plugins/api.py, and plugins/README.md is the author's quick guide. This page is the friendly map; those two files are the territory.

Quick start

A complete, working plugin in one file.

Create a folder under plugins/ with an __init__.py. Subclass TrackerPlugin, implement launch(), and expose your class as PLUGIN:

plugins/ └── my_plugin/ └── __init__.py # one file is enough to start
plugins/my_plugin/__init__.py
from PyQt5.QtCore import Qt
from PyQt5.QtWidgets import QLabel

from app.plugins import TrackerPlugin


class MyPlugin(TrackerPlugin):
    NAME = "My Plugin"                 # shown in the Plugins panel
    DESCRIPTION = "Says how many points are tracked."

    def launch(self):                  # called when the user clicks the entry
        w = QLabel(f"{self.ctx.n_active} points tracked", parent=self.ctx.window)
        w.setWindowFlags(Qt.Window)
        w.setWindowTitle(self.NAME)
        w.show()
        return w                       # return the window so it stays alive


PLUGIN = MyPlugin                      # how the app finds your plugin

Then, in the running app, click Plugins → Reload Plugins (no restart needed). Your plugin appears as a launch button; click it to run launch().

The edit loop. Edit a plugin → Reload Plugins → click it again. Reload re-imports every plugin module from scratch, so your changes take effect immediately. Plugins → Open Plugins Folder… opens this directory in your file browser.

Frames: global vs cut

The one concept that trips everyone up — internalize it first.

There are two ways to index a frame, and they don't agree:

  • Global index — position in the full loaded folder, 0 … ctx.n_total_images − 1. Every index argument and frame property on ctx is global.
  • Cut index — position within the tracked range, where cut 0 = the reference frame. The tracked-data arrays from coords() / track_status() are cut-indexed on axis 0.
tracked range — reference → last
global 01 23456 7
cut 01234
reference_index = 2 → cut 0 last_index = 6 → cut 4 coords()[0] is the reference frame

Convert freely with the two helpers on ctx:

global ⇄ cut
cut = ctx.global_to_cut(ctx.current_index)   # global - reference_index
glo = ctx.cut_to_global(0)                   # reference_index + cut

coords = ctx.coords()        # (frames, points, 2), cut-indexed
ref_points = coords[0]       # positions on the reference frame
cur_cut = ctx.current_cut    # cut index of the shown frame, or None if outside range

Don't index coords() with a global index. coords[ctx.current_index] is wrong unless the reference happens to be frame 0. Use coords[ctx.current_cut], and guard for current_cut is None (the displayed frame can sit outside the tracked range).

Anatomy & lifecycle

The TrackerPlugin base class, and how the app discovers and runs it.

The base class

Subclass TrackerPlugin (from app.plugins). Only launch() is required:

class TrackerPlugin
NAME : strattr
Display name in the Plugins panel. Defaults to "Unnamed Plugin".
DESCRIPTION : strattr
One-line tooltip for the launch button. Optional.
__init__(self, ctx)
The manager instantiates your class once, passing a fresh PluginContext. The base stores it as self.ctx. Override to set up state (call super().__init__(ctx)).
launch(self) → QWidget | None
Required. Build and show() your window, then return it so the manager keeps it alive. Called each time the user clicks the entry. Returning None is allowed only if you hold your own references.
on_unload(self) → None
Optional. Called on reload/unload — remove overlays and end interactions here. Default is a no-op.

And at module level, name your class so the loader can find it:

__init__.py
PLUGIN = MyPlugin    # required: the manager reads this to instantiate your plugin

Reusing one window

The two-line launch() above builds a new window every click. For a tool you reopen often, cache it instead — the pattern the bundled examples use:

reuse a single window
class MyPlugin(TrackerPlugin):
    NAME = "My Tool"

    def __init__(self, ctx):
        super().__init__(ctx)
        self._window = None

    def launch(self):
        if self._window is None:
            self._window = MyWindow(self.ctx)
        self._window.show()
        return self._window

    def on_unload(self):
        if self._window is not None:
            self._window.close()
            self._window = None

How discovery works

On startup (and on every reload) the manager walks plugins/ and treats a folder as a plugin when all of the following hold:

  • it is a directory whose name does not start with . or _;
  • it contains an __init__.py (so it imports as the package plugins.<folder>);
  • that module exposes PLUGIN = YourClass (a TrackerPlugin subclass). As a fallback, a lone TrackerPlugin subclass defined in the package is auto-detected.

The folder name is your plugin's id — it's also the key your settings are stored under. Import or discovery errors are caught and surfaced on a disabled button; they never crash the app.

Tracked data

The everyday call is ctx.coords(). It returns the forward-tracked positions of the points that survived cleanup, cut-indexed on axis 0.

The Metrics object

if not ctx.has_result:
    return

Frames & navigation

Where we are in the sequence — and the one call that moves the app.

ctx — frames (all indices are global)
reference_index : intprop
Global index of the reference frame (= cut 0).
last_index : intprop
Global index of the last tracked frame.
current_index : intprop
Global index of the frame currently shown on the canvas.
current_cut : int | Noneprop
Cut index of the current frame, or None if it's outside the tracked range.
global_to_cut(global_index) → int
global − reference_index.
cut_to_global(cut_index) → int
reference_index + cut.
set_current_frame(global_index)mut
Move the app's current frame (clamped to the loaded range). Drives the same path as the Current slider — updates canvas, status bar and tools, and emits frame_changed.
set_reference_frame(global_index)mut
Move the reference (start) frame, clamped to 0 … last_index. Drives the Reference slider — re-scopes the tracked range and, since the ROI lives on the reference frame, clears any ROI & seed features (emits roi_changed).
set_last_frame(global_index)mut
Move the last frame, clamped to reference_index … last loaded frame. Drives the Last slider — re-scopes the tracked range.

Changing the range can stale a result. Like the GUI sliders, these setters leave an existing tracking result untouched — they don't prompt or discard. After moving the reference or last frame, coords() no longer aligns with the new reference_index until you re-track. They also clamp to the invariant 0 ≤ reference ≤ last < total, so a value past a bound is pinned to it.

Canvas overlays

Draw your own graphics on top of the live frame.

Register a painter fn(painter, ctx). It runs on every repaint, in screen space, after the built-in overlays. The canvas stores everything in image coordinates, so convert each point with ctx.image_to_screen(...) as you draw — marker sizes then stay constant under zoom and pan.

ctx — overlays
add_overlay(fn)
Register an overlay painter fn(painter, ctx). Idempotent. A painter that raises is auto-removed.
remove_overlay(fn)
Unregister it — do this in closeEvent / on_unload.
image_to_screen(x, y) → QPointF
Map an image-space point to widget coordinates (for painting).
screen_to_image(point) → QPointF
Map a widget point back to image coordinates.

Keep painters cheap. They run on the UI thread on every paint. Cache anything expensive (triangulations, color maps) and recompute only when the relevant signal fires — never inside the painter.

The lifecycle from the displacement_overlay example — register on construction, redraw reactively, remove on close:

plugins/displacement_overlay/overlay.py
        ctx.signals.frame_changed.connect(self._redraw)
        ctx.signals.result_changed.connect(self._invalidate)
        ctx.signals.mask_changed.connect(self._invalidate)

        ctx.add_overlay(self._paint)
        self._redraw()

    def closeEvent(self, event):
        self.ctx.remove_overlay(self._paint)
        super().closeEvent(event)

    def _paint(self, painter, ctx):
        coords = ctx.coords(active_only=True)
        ref_pts = coords[0]
        cur_pts = coords[ctx.current_cut]
        painter.setPen(QPen(QColor(255, 255, 0), 1.2))
        for j in range(cur_pts.shape[0]):
            painter.drawLine(ctx.image_to_screen(*ref_pts[j]),
                             ctx.image_to_screen(*cur_pts[j]))

Mouse capture

Take over canvas clicks to build interactive tools.

Subclass CanvasInteraction and implement only the handlers you need. Every point arrives in image coordinates. While your interaction is active, the ROI and Pan tools switch off so they don't conflict; middle/right-drag still pans.

class CanvasInteraction (all handlers optional)
on_press(self, image_pt, event)
Left-button press at image_pt (a QPointF in image coords).
on_move(self, image_pt, event)
Mouse move (fires continuously — ignore if you only want clicks).
on_release(self, image_pt, event)
Left-button release.
on_cancel(self)
The interaction was replaced or ended — clean up here.

Activate and release through ctx:

plugins/affine_zones/zones.py
from app.plugins import CanvasInteraction


class ZoneDrawTool(CanvasInteraction):
    """Collects polygon vertices from canvas clicks while the user draws a zone."""

    def __init__(self, window):
        self.window = window
        self.vertices = []

    def on_press(self, image_pt, event):
        self.vertices.append((image_pt.x(), image_pt.y()))
        self.window.on_draw_progress()


# elsewhere, to start / stop drawing:
def _start_zone(self):
    self._tool = ZoneDrawTool(self)
    self.ctx.begin_canvas_interaction(self._tool)
    self.ctx.status("Click to add zone vertices, then press “Finish Zone”.")

Filtering points

The single mutation to the tracked data — and it's undoable.

Aside from navigating and re-scoping frames, plugins read everything but change almost nothing about the tracked data. The one exception is apply_keep_mask: it filters tracked points by a boolean keep-mask, recorded on the Cleanup dialog's undo stack.

ctx — mutation
apply_keep_mask(keep)mut
keep is a bool array of length P or n_active (other lengths raise ValueError). Points marked False leave the active set. Monotonic — it only ever shrinks the set, never resurrects filtered-out points. Emits mask_changed; the user can Undo it in the Cleanup dialog.

From affine_zones — drop the RANSAC outliers in a zone (an n_active-length mask):

plugins/affine_zones/zones.py
keep = np.ones(self.ctx.n_active, dtype=bool)
keep[local_idx[~inliers]] = False
dropped = int((~inliers).sum())
if dropped == 0:
    return
self.ctx.apply_keep_mask(keep)
self.ctx.status(f"Dropped {dropped} outlier(s). Undo in the Cleanup dialog.")

Custom Exporter

plugins/custom_exporter/
Read data · export

The simplest shape. A window with format options that exports ctx.coords() to CSV, MATLAB .mat, or NumPy .npz, and remembers your choices via settings. SciPy's savemat is imported lazily, only when you export .mat.

Displacement / Strain Overlay

plugins/displacement_overlay/
Canvas overlay

Draws displacement vectors and an interpolated strain field over the frame. Triangulates the reference points with SciPy's Delaunay, colors each triangle by strain, and caches the result per frame — recomputing only when result_changed / mask_changed fires.

Teaches: the overlay lifecycle, screen-space painting with image_to_screen, signal-driven redraws, and the reused-window pattern.

Conventions & gotchas

The handful of things that bite, distilled.

  • Global vs cut. Every ctx index is global; coords() is cut-indexed (coords[0] = reference). Convert with cut_to_global / global_to_cut, and remember current_cut can be None.
  • Parent your windows to ctx.window and set the Qt.Window flag so they float independently and return them from launch() so they aren't garbage-collected.
  • Always undo your canvas hooks in closeEvent / on_unload: remove_overlay(...) and end_canvas_interaction().
  • Treat returned arrays as read-only. Don't mutate coords(), active_mask, or metrics in place. The only legitimate change to the point set is apply_keep_mask.
  • Overlays must be fast. Cache heavy work; recompute on the matching signal, not inside the painter.
  • Import optional deps lazily (inside the function that needs them, in a try/except) so merely loading your plugin never pulls in SciPy/matplotlib at startup.
  • Failures are contained, not silent. A bad import disables the button, a throwing overlay removes itself, a failing launch() shows a dialog — read the message and fix it.
